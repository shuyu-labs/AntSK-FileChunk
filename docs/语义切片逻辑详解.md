# AntSK-FileChunk 语义切片逻辑详解

## 概述

AntSK-FileChunk 的语义切片系统是一个基于语义理解的智能文本分割工具，它能够根据文本的语义连贯性智能地将长文档分割为合理的片段。该系统不仅考虑文本长度，更重要的是保持语义的完整性和连贯性。

## 核心组件架构

### 1. 核心组件关系图

```
SemanticChunker (主控制器)
├── DocumentParser (文档解析器)
├── SemanticAnalyzer (语义分析器)
├── ChunkOptimizer (切片优化器)
└── QualityEvaluator (质量评估器)
```

### 2. 数据流程

```
输入文档/文本
    ↓
文档解析 (DocumentParser)
    ↓
段落预处理
    ↓
语义向量计算 (SemanticAnalyzer)
    ↓
智能切片 (语义边界检测)
    ↓
切片优化 (ChunkOptimizer)
    ↓
质量评估 (QualityEvaluator)
    ↓
输出最终切片
```

## 详细工作流程

### 第一阶段：文档解析与预处理

#### 1.1 文档解析
- **功能**: 将各种格式的文档解析为统一的段落结构
- **输入**: 文件路径或纯文本
- **输出**: 结构化的段落列表

#### 1.2 文本预处理
```python
def _preprocess_paragraphs(self, paragraphs: List[Dict]) -> List[str]:
```

**处理步骤**:
1. **文本清理**: 移除多余空白字符、特殊字符
2. **长度过滤**: 过滤过短的段落（< 20字符）
3. **格式规范化**: 统一空白字符格式

**对于纯文本输入的特殊处理**:
```python
def _split_text_to_paragraphs(self, text: str) -> List[str]:
```
- 按双换行符分割段落
- 超长段落按句号进一步分割
- 避免单个段落过长影响语义分析

### 第二阶段：语义分析

#### 2.1 语义向量计算
```python
def compute_embeddings(self, texts: List[str]) -> np.ndarray:
```

**技术实现**:
- **模型**: SentenceTransformer（默认: "all-MiniLM-L6-v2"）
- **预处理**: 文本长度限制（中文512字符，英文256字符）
- **向量归一化**: 确保相似度计算的准确性
- **批处理**: 批量大小32，提高计算效率

**容错机制**:
```python
fallback_models = [
    "paraphrase-MiniLM-L6-v2",
    "all-mpnet-base-v2", 
    "distilbert-base-nli-stsb-mean-tokens"
]
```

#### 2.2 语义相似度计算
- **方法**: 余弦相似度（Cosine Similarity）
- **范围**: 0-1，越接近1表示语义越相似
- **应用**: 判断段落间的语义连贯性

### 第三阶段：智能切片算法

#### 3.1 核心切片逻辑
```python
def _semantic_chunking(self, paragraphs: List[str], embeddings: np.ndarray, metadata: Dict) -> List[TextChunk]:
```

**算法流程**:

1. **初始化状态**:
   ```python
   current_chunk_indices = []      # 当前切片包含的段落索引
   current_chunk_content = []      # 当前切片的内容

   ```

2. **段落遍历决策**:
   对每个段落，判断是否应该开始新切片：
   ```python
   should_start_new_chunk = self._should_start_new_chunk(
       current_chunk_indices,
       current_chunk_length,
       para_length,
       embeddings,
       i
   )
   ```

3. **切片边界判断条件**:

#### 3.2 切片边界决策算法

```python
def _should_start_new_chunk(self, current_indices, current_length, new_para_length, embeddings, new_para_index) -> bool:
```

**决策条件** (按优先级排序):

1. **硬性长度限制**:
   ```python
   potential_length = current_length + new_para_length
   if potential_length > self.config.max_chunk_size:  # 默认1500字符
       return True
   ```

2. **语义连贯性检查**:
   ```python
   semantic_coherence = self._calculate_semantic_coherence(current_indices, new_para_index, embeddings)
   if semantic_coherence < self.config.semantic_threshold:  # 默认0.7
       if current_length >= self.config.target_chunk_size:  # 默认800字符
           return True
   ```

#### 3.3 语义连贯性计算

```python
def _calculate_semantic_coherence(self, current_indices, new_index, embeddings) -> float:
```

**计算方法**:
1. 提取新段落的语义向量
2. 计算新段落与当前切片中所有段落的相似度
3. 返回平均相似度作为连贯性得分

**公式**:
```
coherence_score = mean([cosine_similarity(new_embedding, existing_embedding) 
                       for existing_embedding in current_chunk_embeddings])
```

#### 3.4 重叠处理机制

```python
def _calculate_overlap(self, indices: List[int], content: List[str]) -> Tuple[List[int], List[str]]:
```

**重叠策略**:
- **重叠比例**: 可配置（默认10%）
- **重叠内容**: 取当前切片的最后几个段落
- **目的**: 保持上下文连续性，便于信息检索

### 第四阶段：切片优化

#### 4.1 优化流程

```python
def optimize_chunks(self, chunks: List) -> List:
```

**优化步骤**:
1. **合并过小切片** (`_merge_small_chunks`)
2. **分割过大切片** (`_split_large_chunks`) 
3. **优化切片边界** (`_optimize_boundaries`)
4. **后处理清理** (`_post_process_chunks`)

#### 4.2 小切片合并逻辑

**触发条件**: 切片长度 < `min_chunk_size` (默认200字符)

**合并策略**:
1. 检查相邻小切片是否可以合并
2. 确保合并后长度不超过 `max_chunk_size`
3. 优先与后续切片合并，保持语义连续性

#### 4.3 大切片分割逻辑

**触发条件**: 切片长度 > `max_chunk_size` (默认1500字符)

**分割策略**:
1. **句子边界分割**: 优先按句子分割
   ```python
   sentences = re.split(r'[。！？；]', content)  # 中文
   sentences = re.split(r'[.!?;]', content)     # 英文
   ```
2. **强制字符分割**: 无法按句子分割时的备选方案
3. **保持重叠**: 分割后的子切片间保持配置的重叠比例

### 第五阶段：质量评估

#### 5.1 评估指标

1. **语义连贯性得分**: 切片内段落间的平均相似度
2. **完整性评估**: 切片是否包含完整的语义单元
3. **长度分布**: 切片长度的统计分析

#### 5.2 质量分数计算

```python
def _calculate_chunk_semantic_score(self, paragraph_indices, embeddings) -> float:
```

**计算公式**:
```
semantic_score = mean([cosine_similarity(emb_i, emb_j) 
                      for i in range(n) for j in range(i+1, n)])
```

## 配置参数详解

### ChunkConfig 类配置项

```python
@dataclass
class ChunkConfig:
    min_chunk_size: int = 200           # 最小切片字符数
    max_chunk_size: int = 1500          # 最大切片字符数  
    target_chunk_size: int = 800        # 目标切片字符数
    overlap_ratio: float = 0.1          # 重叠比例 (10%)
    semantic_threshold: float = 0.7     # 语义相似度阈值
    paragraph_merge_threshold: float = 0.8  # 段落合并阈值
    language: str = "zh"                # 语言设置
    preserve_structure: bool = True     # 保持文档结构
    handle_special_content: bool = True # 处理特殊内容
```

### 参数调优建议

| 参数 | 用途 | 调优策略 |
|------|------|----------|
| `semantic_threshold` | 控制语义边界敏感度 | 值越高切片越大，语义连贯性要求越严格 |
| `target_chunk_size` | 理想切片大小 | 根据下游任务需求调整（如RAG检索） |
| `overlap_ratio` | 切片间重叠度 | 提高可以增强上下文，但会增加存储成本 |

## 算法优势与特点

### 1. 语义感知切片
- **传统方法**: 固定长度或简单分隔符切片
- **本系统**: 基于语义相似度的智能边界检测
- **优势**: 保持语义完整性，避免语义单元被割裂

### 2. 自适应长度控制
- **动态调整**: 在保证语义连贯的前提下动态调整切片大小
- **多层约束**: 最小/目标/最大长度的三层约束机制
- **优化处理**: 后处理阶段的合并分割优化

### 3. 多语言支持
- **中文**: 基于字符的Token估算，中文分词支持
- **英文**: 基于单词的处理，NLTK集成
- **扩展性**: 易于添加其他语言支持

### 4. 质量保证
- **多维评估**: 语义连贯性、完整性、长度分布等多维度评估
- **统计分析**: 详细的切片质量统计信息
- **可视化友好**: JSON格式输出，便于分析和可视化

## 性能考虑

### 1. 计算复杂度
- **语义向量计算**: O(n) - 段落数量线性增长
- **相似度计算**: O(k) - k为每个切片的段落数，通常很小
- **总体复杂度**: O(n) - 对大文档处理友好

### 2. 内存优化
- **批处理**: 语义向量批量计算，减少GPU显存占用
- **向量归一化**: 减少存储空间，提高计算效率
- **流式处理**: 支持大文档的分段处理

### 3. 模型优化
- **轻量级模型**: 默认使用MiniLM模型，平衡效果与速度
- **模型缓存**: 模型加载后缓存，避免重复加载
- **容错机制**: 多个备选模型，确保服务可用性

## 使用示例

### 基本使用

```python
# 初始化配置
config = ChunkConfig(
    target_chunk_size=1000,
    semantic_threshold=0.75,
    language="zh"
)

# 创建切片器
chunker = SemanticChunker(config=config)

# 处理文件
chunks = chunker.process_file("document.txt")

# 处理纯文本
chunks = chunker.process_text("长篇文本内容...")

# 获取统计信息
stats = chunker.get_chunking_statistics(chunks)

# 保存结果
chunker.save_chunks(chunks, "output.json")
```

## 总结

AntSK-FileChunk的语义切片系统通过集成先进的语义分析技术和智能的切片算法，实现了高质量的文本分割功能。系统不仅考虑文本的物理长度限制，更重要的是保持语义的完整性和连贯性，为下游的文本处理任务（如RAG检索、文档分析等）提供了高质量的文本片段。

该系统的核心优势在于：
1. **智能边界检测**: 基于语义相似度的边界识别
2. **多层优化**: 从初步切片到最终优化的多阶段处理
3. **质量保证**: 完善的质量评估和统计分析
4. **灵活配置**: 丰富的配置参数适应不同场景需求
5. **高性能**: 优化的算法设计和计算流程

这使得AntSK-FileChunk成为一个功能强大、性能优异的智能文本切片解决方案。
